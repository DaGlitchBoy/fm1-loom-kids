# LOOM Kids • playable instrument design and implementation brief

Design only. Baseline: feature branch `feat/loom-kids-ui`, commit `4fe6e52`. The controls below supersede the milestone-one Kids mappings. Implement one numbered delivery at a time on a new feature branch. Start with the emulator. Never flash, install, connect to or test against physical hardware.

## Architecture decision

Keep LOOM-8's audio engine, factory sounds/kits, project readers, eight tracks, sequencer, platform emulator and Studio fallback. Keep the existing eight numbered, colored track icons (drawn from primitives) and redraw only changed screen regions. Replace the Kids input dispatch and panel layout. Using a clean upstream LOOM checkout would add work to recover the protected working copy, icons, browser entry and tests. Building directly on fm1-base is a credible alternative for a new synthesizer, but here it means rebuilding and validating drums, polyphony, effects, playback, recording, presets and project handling before testing the instrument. A separate browser instrument would make the Mac demo easier to draw but postpone the FM1 port and duplicate the audio behavior. None of those alternatives fixes the storage and history requirements for free. No other firmware has been benchmarked for this proposal.

Build an independent Kids controller with one mapping for global inputs, a single live-note path, small per-panel mappings and a song library service. The existing engine owns playback state. Kids owns musical choices that LOOM does not currently represent, e.g. chord mode, scale and remembered effect amounts. Define versioned song metadata and explicit load defaults for those choices. Derive visuals from the same values that reach audio. Keep writes, serialization and history allocation outside the audio/render paths. Preserve Studio projects and its regression suite. New DSP/storage work is a subsequent milestone, separate from the old UI-only scope.

## One instrument to learn

The eight fields on HOME identify tracks throughout the song, even when you change a track's instrument. The selected track has a conspicuous outline, its actual sound name, and brief feedback when played. During FX, SEL, EDIT, GLO and ARP exactly this layout stays up. Only the strip underneath changes: one panel icon + short name, then four permanently aligned knob labels and current values/mini-graphs. Use the real panel button names. Color reinforces shape and position. ENV, LFO and the two SEQ views replace the tile area. Keep track identity and transport visible there as well.

| Physical control | Contract throughout Kids |
| --- | --- |
| SELECT, turn | Previous/next **track**, cyclic 1–8. Keyboard playing never selects a track. |
| PRESETS, turn | Previous/next nonempty **category**, cyclic. Suggested order: Keys, Bass, Drums, Pads, Leads, Plucks, Textures, User (when populated). Apply the last sound used by this track in that category or its first sound. |
| ALGORITHM, turn | Previous/next **individual preset** or kit in that category, cyclic in both directions, including at the ends. Actual preset name visible after each change. |
| OCT− / OCT+ | Lower/raise the live and insertion root register by one octave. Octave never edits a page, length, slot or parameter. Clamp at playable limits. Drum trigger identities stay consistent where a kit has no pitched keyboard. |
| PLAY | Start/stop transport from any musical page. Returning HOME or opening a panel never stops playback. |
| REC (proposed) | Tap to arm/disarm overdub of the selected track. If stopped, PLAY starts it. Record live keyboard input on HOME, normal panels, graphs and Performance. Steps uses direct editing only. Show armed/recording distinctly, and disarm explicitly on entering Steps or changing the record target. |
| SAVE | Save to free space immediately. The library rules below apply on every page. |
| HOME | Tap to return to the playable eight tiles with base knobs. Hold to show Undo/Redo; only K1 turns replay history. A used hold must never also trigger a tap. |

The three global encoders retain their roles on every musical page, including GLO and both SEQ views. A PIN/overwrite dialog consumes input without accidentally changing music. Keep an explicit adult Studio entry via the emulator's labelled control and an adult option on GLO (for example a labelled on-screen control); SEL is now Delay. Make reader/keyboard navigation to the adult control part of browser acceptance.

**One rule for illuminated toggles.** FX, SEL, ENV, LFO, EDIT and ARP remember independent enabled states for the selected track. Press an unlit button: enable, light, show controls. Press a lit button: bypass, extinguish, return to HOME controls, even if another panel had focus. HOME or GLO changes focus without disabling anything. Selecting another track updates the LEDs and values to that track. Panel icon shows focus; LEDs show what is audible/enabled. Turning something on recalls its settings, with a useful audible first-use default. On LFO, K1 sets the same enable bit as its button. A drum kit or engine which cannot support a mapping must have a documented implementation and audible test before that control is exposed.

## What the four knobs do

| Button / view | K1 | K2 | K3 | K4 | Visual |
| --- | --- | --- | --- | --- | --- |
| HOME | Track mix volume | Track loop length 16 / 32 / 64 steps | Chord mode | Scale | Eight tiles + speaker, loop, chord, scale strip |
| FX | Reverb amount | Decay | Room size | Tone | Room / expanding rings under tiles |
| SEL | Delay amount | Feedback (echo repeats) | Synced time | Tone | Progressively smaller echo marks |
| ENV | Attack | Hold | Sustain level | Release | Full envelope graph; edit moves the corresponding segment |
| LFO | Off / On | Destination | Depth | Waveform | Full waveform + moving phase marker driven by musical time |
| EDIT | Low-pass amount | Distortion amount | Bitcrush amount | Chorus amount | Four simple intensity bars; fixed musical recipes |
| GLO | Song BPM | Metronome loudness, zero = off | Song slot 1–16 | Arm/request delete | Song number, occupied/empty, and protection state |
| ARP | Up / Down / Up-down / Down-up / Chaotic | Synced rate | HOME chord mode | HOME scale | Note staircase; LED tracks active state |
| SEQ • Steps | Last touched step/hit velocity | Root for inserting notes | Edit page 1–4 within length | Right → Performance | 16 numbered cells + page and selected hit/root |
| SEQ • Performance | Selected track volume | Selected track length 16 / 32 / 64 | Swing amount | Left → Steps | Eight track rows × 16 columns + current page |

GLO is a settings page with no audio bypass. SEQ opens Steps; K4 is a two-position selector with end stops. Use continuously variable controls for amounts, detents for enumerations. The named track length is the active pattern's loop length for that track. If a song imports a mixture of pattern lengths, editing one pattern must not resize unrelated patterns. A sixteenth-note step means 16 steps per 4/4 bar, so the three choices are one, two and four bars. Shortening hides later notes and preserves them for re-extension.

## Keyboard, chords and recording

- HOME, the overlay panels, ENV, LFO and Performance all use the entire piano keyboard to play. In Steps the 16 white keys toggle cells 1–16; black keys are inert on melodic tracks and select the kit hit on drums. Inserting beyond the current selected length requires lengthening first.
- Every melodic key yields a note in the selected scale. Proposed first release uses tonic C, the keyboard's ordinary pitches in Chromatic, nearest in-scale pitch otherwise, ties down. Key travel remains monotonic, repeated pitches are allowed. Include Chromatic, Major, Natural Minor, Major Pentatonic, Minor Pentatonic, Dorian and Egyptian pentatonic (0, 2, 5, 7, 10). Keep intervals in a table with boundary tests. OCT transposes 12 semitones. No muted black keys in live play.
- Preserve this exact chord order: Single, In Scale, Major (0/4/7), Minor (0/3/7), Power (0/7), Minor 7 (0/3/7/10), Octaves (0/12), Major 7 (0/4/7/11). In Scale uses scale degrees 1/3/5 from the played scale degree, wrapping octaves; in Chromatic use a major triad as a defined fallback. Fixed chord qualities keep their intervals even when only the root is quantized. At range limits move voicing by octaves into range. Resolve actual pitches once per key-down; release exactly the pitches/track owned by that press. Overlapping chords and duplicate quantized pitches need reference counts or equivalent ownership.
- Arp consumes the generated chord or held notes. Use 1/4, 1/8, 1/8-triplet, 1/16 and 1/16-triplet as a first rate list. Up-down starts low, down-up starts high; avoid duplicated endpoints. Chaotic uses the existing musical random behavior or a reproducible Kids equivalent. Record the underlying played pitches once, not every generated arp subdivision plus the chord. Native steps can hold four notes. State the overdub rule when a fifth pitch lands (proposed: keep the first four distinct notes, flash a full-step indicator). Test polyphonic patches, monophonic patches and drum tracks separately. Drum notes are hits; pitched chord/scale modes should show a kit-specific inactive indication where inappropriate.
- Switching sound categories must include **Drums on any track**. LOOM encodes melodic pitches and drum-hit masks in the same step bytes. Never reinterpret one as the other. Proposed: keep a typed alternate pattern bank for material of the other kind, allocated sparsely outside the audio callback. First switch opens an empty bank of the new kind, switching back restores the original. Preserve length, active pattern and time position; isolate type-specific hit settings/automation, save both banks and provide undo. Prototype packing and memory before committing to a device representation. Show a kit/note icon during the switch.
- Performance displays the selected track's current 16-step page across the eight aligned rows. During play follow its page at steps 17, 33 and 49, then wrap at its loop end. Show page/total at the top, occupancy and each track's playhead when within that window. Dim out-of-range cells on shorter tracks. While stopped, reuse the last valid viewed page. The child can play over the overview and hear every live key; the grid writes only when REC is armed. K3 controls selected track/pattern swing with straight at minimum. Use the straight timing template with a variable shuffle amount for new songs.
- In Steps K3 manually pages and clamps to 1, 2 or 4 valid pages. Playback does not pull the editing page away. K1 targets the most recently touched cell on this track/pattern; for a chord the step velocity is shared, for drums target just the selected hit. After removing a note, adjusting velocity sets its next insertion velocity without resurrecting it. Before any selection show “–”. K2 sets the next melodic root, showing note name/register; existing notes stay put. For kits show the black-key-selected hit instead of promising melodic root changes.

## What the engine supplies, and what to build

| Area | Existing LOOM capability | Economical implementation / gap |
| --- | --- | --- |
| Sound and sequencing | Eight instruments, genuine synth/kit presets, independently timed patterns to 64 steps, step locks, live input and recording | Reuse load/apply, note/transport and recorded event paths. New controller, category wrap, chord mapping, type switching, overview and history integration. Keep levels independent of preset changes. |
| Reverb and delay | Two shared send processors; only the second has reverb memory. Reverb modes expose size/decay/tone; delay exposes synced time and feedback. | Reserve send I for delay and II for reverb. Amount and enable belong to each track; **tail controls are shared across the song**. Label that on the panel; preserve relative per-hit kit sends. Bypass stops new sends, lets existing tails fade. Choose a suitable reverb model with independent decay/size/tone. |
| Delay divisions | Clocked delay with finite delay line; slow tempos can push a division beyond capacity | Start with common musical labels such as 1/16, 1/8T, 1/8, dotted 1/8 and 1/4. An eighth-note triplet is **1/3 of a beat** in 4/4. One third of a whole note is a different duration. Show only values the current tempo/buffer can deliver, including after tempo changes. Test impulse spacing against the label; never silently show a longer delay than is heard. |
| Envelope | Melodic voices have ADSR; kit models have different amplitude controls | True hold needs a timed plateau. Use attack → hold → short fixed decay → sustain → release; note-off during any phase starts release from current level. Off restores the preset envelope. For kits prototype equivalent hit/gate shaping; specify one-shot release behavior. Graph uses actual time/level parameters. Do not label decay as hold. |
| LFO | Waveforms, modulation destinations and synchronized modulation exist, with distinct global/per-track paths | Use one per selected track. Proposed fixed period = one 4/4 bar because all four knobs are assigned. Support volume and cutoff initially, then drive once the drive insert exists. Sine, triangle, saw, square. Show true phase while running; knob changes immediately redraw the shape. No UI timer drives audio. |
| Four quick effects | Filtering, character processing and shared chorus exist; drive/crush are alternatives in one character slot | New simultaneous routing is required. Prototype filter → drive → crush with a separate chorus send/return or equivalent measured insert. Chorus must coexist with both original sends. Zero = dry, full = strongest calibrated setting, with conservative output gain. Panel off bypasses all four and remembers amounts. Compare real waveforms/levels at equal note velocity. |
| Click / tempo | Native tempo and beat click; fixed click amplitude | Add independent click gain; zero is silent. Verify changing click gain leaves instrument mix unchanged. |
| Library / undo | Three native project slots in a constrained storage pool; one interchangeable undo state | A sixteen-song library and five reversible edits including disk writes require separate services. Do not change a slot constant or allocate five full RAM copies per turn. |

## Song shelf, PIN and five-step history

A Kids “song” means a complete working project with eight resolved sounds and kits, patterns, arrangement, levels and Kids-specific musical settings. Selecting a different preset tomorrow must not change a saved song. Snapshot the actual parameter values and song-owned kit settings. Define sample-asset references and missing-sample behavior; references alone do not embed user audio. Include a version and integrity check. Keep the current in-memory working copy detached from the Studio slots.

1. **Browse and load.** GLO K3 highlights a numbered slot and shows occupied/empty. Turning it previews the slot identity only. A labelled GLO action (proposed: EDIT while GLO's load prompt is open) confirms Open. HOME cancels. For an occupied slot, protect unsaved work with explicit save-as-copy / discard / cancel choices before loading. For an empty slot, keep the current work and select that destination for SAVE. Do not make merely scrolling the shelf load a project.
2. **Save.** With protection on, one SAVE writes the selected slot if empty, otherwise the next empty slot in cyclic order. Saving revisions makes new copies while space remains. Indicate “Saved 04” only on successful commit. When full, show the exact target, obtain the adult PIN and confirm replacement. No auto-overwrite or background Kids autosave. With protection off, SAVE writes the selected slot immediately, even if occupied.
3. **Delete.** K4 on GLO is a request, not a continuous destructive control. A right detent arms “Delete 04?”; left or HOME cancels. Show the target name/number, require PIN when protected, then a deliberate confirmation. Debounce so holding or spinning cannot repeat the delete. Empty slots cannot be deleted.
4. **Five GLO presses.** Five distinct taps within a proposed three-second window open a visible change-of-protection prompt. Given the earlier child-safety goal, the recommended interpretation is to enter the **current adult PIN once** to switch save/delete protection off for this session. Show an open lock and an explicit warning; five taps can re-enable. If five taps *alone* must disable it, that is a different product rule: a child can use that exact sequence too. Settle this choice before building the library. Either version keeps Studio access independent; use a labelled adult entry rather than taking SEL away from Delay. For a persistent library, enroll an adult verifier per browser profile; reopening or cancelling enrollment must never authorize destructive operations on an existing protected bank. Enable protection on restart.
5. **Undo/redo.** Holding HOME shows a history strip, the next Undo/Redo action name and available counts. Each K1 detent replays one complete action; no encoder acceleration. Five committed actions across tracks and pages; a sixth evicts the oldest. A continuous knob sweep is one action, one chord insertion/preset selection including type change is one action, one recording take is one action. Include parameter/toggle edits, pattern contents and lengths, a loaded/replaced working project, first save, overwrite and delete. Undoing a new save restores an empty slot, undoing overwrite/delete restores exact prior slot bytes, redo reapplies the same transaction. A new edit clears redo. No generic delete/overwrite permission is granted by replay. Scope history to the session, invalidate stale transactions if the slot has changed elsewhere. Navigation, auditions, passcodes, permissions, acknowledgements and the passage of playback time are outside musical edit history.
6. **Storage and failure.** Use an emulator-side versioned sixteen-slot bank: transactional browser storage (e.g. IndexedDB), file-backed equivalent for native tests. Keep five small musical deltas in memory; journal larger before/after images for saves, loads, recordings and destructive edits outside the real-time path. First validate pack/unpack including custom presets, drum overrides and alternate note types. Quota exhaustion, an interrupted write or failed PIN leaves the slot, working copy and history cursor intact. If five protected backups do not fit, refuse the operation with a clear message. No library-wide backup blob on every knob turn. The existing three-slot device store is a separate backend. Do not promise 16 device slots before measuring worst-case capacity, history and write wear.
